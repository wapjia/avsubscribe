# AV 影片订阅

飞牛 fnOS FPK 应用，通过 M-Team API 搜索女优影片并提交到 qBittorrent。

## 功能

- 手动维护女优、附加关键字和各自的下载目录。
- 每条订阅可维护番号黑名单；黑名单中的番号不会新建下载或提交洗版升级。
- 定时轮询 M-Team，可手动立即检查。
- M-Team 请求之间通过应用状态目录中的跨进程锁统一间隔至少 1 秒；检测到站点限流后停止本轮并进入冷却，避免并发 CGI 请求绕过节流。
- 立即检查使用持久 FIFO 队列；短时间提交的多个订阅检查不会互相覆盖，旧版单条队列状态会在升级后兼容读取。
- 按同一订阅内的番号去重，保存下载任务状态。
- 新订阅命中其他订阅 SQLite 索引中仍存在的同番号影片时，验证 M-Team 详情中的女优后复用本地文件：同一文件系统创建硬链接，跨文件系统回退复制；不会重复提交下载，也不会跨订阅洗版删除源文件。
- 扫描订阅目录内已存在的视频番号，并将番号、文件清单和分级索引保存在 SQLite；优先采用 M-Team 缓存的标签与短描述分级，缺失时回退到 NFO/文件名。文件删除后下一次目录刷新或后台扫描会同步删除对应索引记录。
- 创建订阅时识别目标目录内已存在的视频番号，避免重新提交；已有较低版本会在新版本下载完成后清理。
- 订阅默认排除非中文影片，只提交内嵌中文或中文字幕版本；可以在添加或编辑订阅时关闭。
- 可对每个订阅启用洗版：先比语言（内嵌中文 ＞ 中文字幕 ＞ 非中文），语言相同再比分辨率（4K ＞ 1080p ＞ 其他）。编码信息会展示，但 x264/x265 差异不会单独触发线上洗版。新版完整下载后才删除旧任务及其数据。设置中另有默认关闭的“洗版本地重复番号”开关，只比较同一女优名下配置的订阅目录。
- 下载前读取 M-Team 资源详情，核对详情内容是否包含当前订阅的女优名；未找到时跳过该资源并记录原因，避免把其他女优的影片下载到错误目录。
- 洗版会停止旧资源做种。应用只清理自己记录的该番号旧任务。
- 完成下载后只为 M-Team 标记“外挂中文字幕”的资源调用 `POST /subtitle/list?id=<影片M-Team ID>` 读取绑定字幕；多个中文字幕按下载量选最高者，再通过 `POST /subtitle/genlink?id=<字幕ID>` 和 `GET /subtitle/dlV2?credential=<凭据>` 下载。字幕保存为 `<视频文件名>.MT.<语言>.<扩展名>`，如 `SNOS-047-破解.MT.zh-HK.srt`；已保存检查状态，避免每轮重复请求。
- 订阅详情页点击本地视频文件名会调用 fnOS `openFile`，由系统按默认方式打开视频。此功能需要 fnOS 1.2.0401 及应用中心 1.34.0 或更新版本。
- 下载完成后按影片 M-Team ID 关联字幕条目；同番号但关联其他视频 ID 的字幕不会使用，多个关联字幕按下载量选择最高者。字幕保存为 `<视频文件名>.MT.<语言>.<扩展名>`，如 `SNOS-047-破解.MT.zh-HK.srt`；已保存检查状态，避免每轮重复请求。
- 同一资源被多个订阅命中时，复用下载器中的任务；下载完成后复制到各订阅目录，并在最后一个订阅升级后再清理旧任务。
- qBittorrent 添加接口返回 `Ok.` 或包含成功计数与种子哈希的 JSON 时，均按实际添加结果记录任务。
- 新下载的保存位置为「订阅下载目录/番号」，再应用 qBittorrent 路径映射。「立即检查」和「修复数据」会归档所选范围内的已有影片及配套 NFO、字幕。已关联的完整种子由 qBittorrent 移动，独立文件在同一文件系统内移动。目标重名、种子未完成或包含范围外影片时保留原文件并记录原因。
- 封面和截图保存于视频所在目录。完整封面为 `fansrt.<扩展名>`，最右侧 47% 保持原高裁成 `poster.<扩展名>`，截图按 `screenshot-序号.<扩展名>` 命名。多个番号共用一个目录时，图片名加番号前缀。NFO 用相对文件名记录图片。海报裁剪使用 Pillow 或系统 FFmpeg。
- 检查或修复时，已绑定 M-Team ID 的影片会重新生成缺少有效 M-Team ID 的同名 NFO。写入成功后原子替换原文件，已有 M-Team ID 的 NFO 继续按字段更新。
- qBittorrent 已存在相同种子但订阅目录没有对应视频时，先将任务保存目录切换为该订阅映射后的下载器目录，再对种子执行强制校验；若新保存位置缺少数据，qBittorrent 会补下载。不会自动硬链接文件，手动暂停的任务不会被后台检查启动。
- 补全本地视频的 M-Team ID 由后台调度器执行，界面显示当前阶段与结果，避免遍历大量 qBittorrent 任务时超过 fnOS CGI 请求时限。
- 设置字幕汇总目录后，每次订阅检查会将语言等级为“中文字幕”且文件名包含 `.MT.` 的本地字幕复制为 `<番号>.<扩展名>`，供 MDC-NG 的女优刮削流程读取；不含标记的字幕跳过，源字幕保留。同番号同扩展名存在多个字幕时选择修改时间较新的文件。
- ID 补全按 qBittorrent 文件列表中的完整保存路径（应用路径映射后）关联种子注释；同番号的多个本地文件逐个核对，修正旧版错误绑定并重取详情，冲突时跳过。仅接受 Tracker 包含 m-team 或 manfuz 的种子。
- qBittorrent SID 缓存在应用状态目录，后台与 CGI 共用；地址和凭据分别隔离。会话返回 HTTP 401/403 时重新认证并只重试一次，避免每次调用都登录。
- 主界面下载任务表实时读取配置下载器的未完成任务，并按任务哈希关联订阅与番号；M-Team 搜索失败但未进入下载器的候选不会显示为下载任务。主界面同时显示检查日志；女优订阅页可查看该目录中已识别的番号与本地视频文件。资源分辨率、编码和语言优先从同名 `.nfo` 读取，并结合文件名参与洗版排序。

## 安装与设置

在 fnOS 安装构建好的 `AVSubscribe.fpk`。首次打开应用后配置 M-Team 个人存取令牌、下载器 Web API 地址和凭据，再添加女优订阅。

下载目录应为飞牛上的绝对路径，并且下载器和应用看到的是同一条路径。请确认应用用户和下载器都有该目录的读写权限。目录不存在或无法完整读取时，女优页会显示具体目录错误；目录可读取但没有番号时才会显示未发现已识别番号。qBittorrent 需启用 Web UI。

令牌、下载器凭据、订阅与任务记录保存在 `/var/apps/AVSubscribe/var/`，文件权限设置为仅应用用户可读写。本地影片索引使用同目录下的 `local-videos.sqlite3`。凭据不会通过设置接口返回。设置或任务等 JSON 状态文件损坏时，应用会保留带 `.corrupt-时间戳` 后缀的原文件副本，并报告错误，不会把损坏内容当作空数据覆盖。

后台空闲时每 24 小时清理一次无订阅引用的封面索引。清理仅移除 `local_video_covers` 中确认无效的登记，不删除磁盘上的图片或影片；暂时无法访问的订阅目录会保留其记录。

M-Team 的分辨率、编码和字幕语言字典长期保存在本地 SQLite。首次使用时下载，遇到字典未收录的编号时才尝试更新该字典，每张字典最多每 24 小时尝试更新一次；影片搜索和每部影片的字幕列表仍按检查流程查询。

女优页面按可见条目补齐 M-Team 展示资料。展示 ID、头像地址和七项资料字段保存在现有 SQLite 的 `actresses` 表，成功结果复用 30 天，未匹配到资料的条目 7 天后再查。桌面悬停头像查看资料，手机可点按头像。

## 构建与测试

在 Linux 或 fnOS 环境安装 `fnpack` 后，可按 fnOS 工具链构建。Windows 开发机可运行仓库自带的兼容打包脚本：

```powershell
python scripts/build_fpk.py
```

运行单元测试：

```powershell
python -m unittest discover -s tests -v
```

打包脚本每次成功构建都会自动递增 manifest 的 patch 版本号，并在仓库根目录生成 `AVSubscribe.fpk` 和 `AVSubscribe-app.tgz`，便于 fnOS 覆盖升级。
